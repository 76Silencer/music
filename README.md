# Vue 3 纯前端音乐播放器 (v4)

这是一个基于 **Vue 3 (Composition API)** 和 **Vite** 构建的纯前端音乐播放器网站。它拥有类似桌面端音乐软件的现代化布局设计、深色毛玻璃 UI 风格，并支持本地音频库扫描与高清无损音乐播放。

在 v4 版本中，我们增强了底层的稳定性，采用了不可变的短哈希 ID 机制，使得分享链接坚如磐石；引入了内置的精美 SVG 兜底封面；并新增了“顺序播放”模式，让播放逻辑更加贴合日常使用习惯！

## ✨ 核心特性

- 📱 **完美的移动端适配**：响应式设计（Tab 切换模式），解决移动端浏览器高度限制，原生级别顺滑的 Touch 拖拽排序。
- 🔗 **一键稳定分享**：播放列表状态实时无感同步至 URL（`?list=xxx`）。底层基于文件 MD5 生成唯一的 **6 位短 Hash ID** 并具备防碰撞滑动窗口机制，即使曲库新增歌曲打乱顺序，你分享的链接也**永远有效**！
- 🎵 **双模式音乐来源**：
  - **云端/内置模式**：将音乐放在服务器上，网站启动时自动扫描，且每首歌分配独立 ID 便于分享。
  - **本地直读模式**：利用 HTML5 网页 API，用户可直接在网页上选择本地电脑的音乐文件夹进行播放，实现真正的“零流量”听歌。
- 🔍 **智能扫描与信息提取**：内置 Node.js 脚本扫描服务器歌曲；无论是服务器歌曲还是本地直读歌曲，均能自动解析提取音频文件内的 ID3 封面图片。
- 🛡️ **优雅的封面兜底机制**：项目内置了纯代码绘制的高质量矢量（SVG）黑胶唱片占位图，全局所有封面元素自带 `@error` 错误捕获，彻底告别图片碎裂。
- 🎧 **播放控制与模式**：支持上一首、下一首、播放/暂停、进度条拖拽、音量调节；支持**顺序播放**（播完即停）、单曲循环、列表循环、随机播放 4 种模式。默认采用更安静的“顺序”模式。
- 📜 **卡拉OK级单字动态歌词**：深度优化的独立字符渲染算法。支持**单字平滑渐变染色**（非整句）、动态预估演唱时间、自动居中对齐、防拖拽重叠，以及点选按钮直接空降播放，全方位兼容 UTF-8 和 GBK 编码防乱码。
- 🖼️ **智能歌单封面墙**：播放列表顶部自动提取前 4 首歌封面，生成精美的单图、左右拼接、或者四宫格封面拼图墙。
- 🔄 **播放列表交互**：支持电脑端鼠标拖拽排序及移动端触摸拖拽排序，快速移除及防重复添加机制。
- 🔎 **实时搜索**：曲库和播放列表均内置搜索框，支持歌名/歌手名即时过滤。

## 🛠 技术栈

- **框架**: Vue 3 (Composition API)
- **构建工具**: Vite
- **核心组件**: HTML5 `<audio>` API, File System Access API (webkitdirectory)
- **多媒体解析**: `jsmediatags` (解析 ID3 音乐标签与封面)
- **样式**: 纯 CSS (Flexbox, CSS Variables, Backdrop-filter) 现代化极简深色主题

## 🚀 本地运行与开发

### 1. 安装依赖
```bash
npm install
```

### 2. 添加你的音乐文件
将你喜欢的 `.mp3` 或 `.flac` 以及同名的 `.lrc` 歌词文件放到 `public/songs/` 目录下。
*(注：项目中已配置了对 `public/songs/` 的 Git 忽略，因此你的本地私有音乐文件不会被误提交到代码仓库中。)*

### 3. 启动开发服务器
```bash
npm run dev
```
启动时，内置脚本会自动扫描 `public/songs/` 目录，生成最新的曲库配置，并自动提取音频内嵌封面存入 `public/covers/`。

## ☁️ 部署指南 (本地 vs 云端部署的歌曲存放区别)

本项目的打包命令：
```bash
npm run build
```
为了优化网站打包体积以及防止每次部署都要上传几百 MB 的音乐文件，**打包脚本 `package.json` 中的 `build` 指令会自动删除生成的 `dist` 目录中的 `songs` 文件夹**，以便你能快速地把极小体积的网页代码推送到服务器。

### 部署与歌曲存放策略：

#### A. 部署到云服务器 (推荐方案)
因为每次打包重新上传所有音乐到云端会极其缓慢，你可以采用以下策略：
1. 正常执行 `npm run build`，拿到干净的 `dist` 目录。
2. 在服务器上配置好 Nginx 代理你的 `dist` 目录。
3. 每次网站更新，你只需要覆盖上传 `dist` 文件夹中几百 KB 的前端代码（如 html/js/css 文件）。
4. **关键点：** 音乐文件怎么处理？请在云服务器的 `dist` 目录下，**手动新建一个名为 `songs` 的文件夹**，然后利用 FTP/SFTP 将你的 `.mp3` / `.flac` / `.lrc` 音乐文件单独、永久地存放在服务器的 `dist/songs/` 目录下即可。前端代码会自动通过相对路径 `./songs/` 去读取它们。

#### B. 访客本地播放模式 (免服务器存储成本)
你甚至不需要在服务器的 `dist/songs/` 里放任何歌曲。
只要你部署好这个纯前端网站，访客打开你的网站后，点击左侧曲库的 **"添加本地音乐文件夹"**，选择他们自己电脑本地硬盘里的音乐文件夹，即可在浏览器中获得完整的音乐播放体验（包括自动读取本地的专辑封面和同名 `.lrc` 歌词）。这种方式完全不消耗你的服务器流量和存储空间。

## 📝 目录结构简析

```text
├── public/
│   ├── songs/           # 开发环境下放置 mp3/flac 和 lrc 文件的目录 (Git已忽略)
│   └── covers/          # 自动从歌曲中提取生成的封面缓存目录 (Git已忽略)
├── src/
│   ├── components/      # UI 组件
│   │   ├── PlayList.vue       # 右侧播放列表
│   │   ├── PlayerControls.vue # 底部播放控制栏
│   │   ├── SongDetail.vue     # 沉浸式歌词详情页
│   │   └── SongLibrary.vue    # 左侧大曲库
│   ├── composables/     # 复用逻辑
│   │   └── useAudioPlayer.js  # 核心全局播放控制、状态管理、本地文件解析逻辑
│   ├── data/            # 自动生成的静态数据配置
│   ├── App.vue          # 主页面布局容器
│   └── main.js          # 项目入口
├── generate-songs.js    # Node.js 音乐扫描与封面提取脚本
└── package.json         # 项目配置与构建脚本
```
